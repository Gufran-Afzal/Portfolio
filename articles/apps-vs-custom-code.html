Shopify apps vs custom code: how I decide

A simple set of questions I ask before recommending an app or writing the feature myself.

By Ghufran Afzal·Jul 30, 2026·1 min read

On this page
  1. Is this a solved, commodity problem?
  2. Is it a layout or presentation problem?
  3. What does it add to the page?
  4. Who maintains it?
  5. What happens if you leave?
  6. My rule of thumb

Both options are valid. The right answer depends on the feature, the team and the long-term cost. Here are the questions I ask.

Is this a solved, commodity problem?

Reviews, subscriptions, loyalty programmes and complex shipping rules are mature problems with dedicated products and ongoing maintenance behind them. Rebuilding them rarely makes sense.

Is it a layout or presentation problem?

A custom section, a size guide layout or a better product gallery is usually theme work. An app that injects it from the outside tends to cost more in performance than the feature is worth.

What does it add to the page?

Many apps load JavaScript and CSS on every page. Before installing one, check what it loads and where. A feature used on one template should not slow down all of them.

Who maintains it?

  • An app is maintained by its vendor, at a monthly cost.
  • Custom code is maintained by you or your developer, with no recurring fee but a real ownership cost.

Pick the one your team is better equipped to live with.

What happens if you leave?

Check how cleanly an app uninstalls. Some leave code behind in the theme. Custom code is portable, but only if it is documented.

My rule of thumb

Use an app for a mature, back-office-heavy feature. Build custom for anything that is mostly about how the storefront looks and feels. When in doubt, prototype the lightest version first and see whether it is enough.
